# 06. 핫월렛 → 콜드월렛 이동 감지 전략서

## 목적
거래소가 내부 지갑 점검/시스템 작업 전에 **핫월렛 → 콜드월렛으로 자금을 이동하는 패턴**을 감지한다.
KAIA 점검 같은 "사전 감지가 어려운" 내부 점검 케이스도 이 패턴으로 시그널 포착 가능.
05번(비정상 출금)과 구분되는 점: 수신 주소가 **동일 거래소의 콜드월렛**.

## 핵심 원리
- 거래소는 시스템 작업/점검 전 리스크 관리 차원에서 핫월렛 자금을 콜드월렛으로 이동
- 특정 네트워크 기반 자산만 이동하면 → 해당 네트워크 입출금 정지 예측 가능
- 전체 자산 이동이면 → 전체 시스템 점검 예측

## 모니터링 대상

### 거래소 월렛 주소 라벨링
| 거래소 | 핫월렛 | 콜드월렛 | 라벨링 소스 |
|--------|--------|---------|-----------|
| 업비트 | 체인별 핫월렛 주소 | 체인별 콜드월렛 주소 | Arkham, Etherscan |
| 빗썸 | 체인별 핫월렛 주소 | 체인별 콜드월렛 주소 | Arkham, Etherscan |

## 핵심 로직

### 1. 핫→콜드 이동 감지
```
각 거래소의 핫월렛 주소에서:
  출금 tx 감지 → 수신 주소가 동일 거래소 콜드월렛인지 확인

판단:
  수신 주소 ∈ 동일 거래소 콜드월렛 라벨 → 내부 이동 확정
  수신 주소 ∈ 미확인 → 05번(비정상 출금)으로 분류
```

### 2. 이동 패턴 분석
```
Pattern A: 특정 네트워크 자산만 이동
  예: KAIA 네트워크 토큰만 핫→콜드 이동
  → 해당 네트워크 입출금 정지 예측
  → 시그널 발행

Pattern B: 전체 자산 대량 이동
  예: ETH, SOL, BTC 등 전 체인 핫→콜드 이동
  → 전체 시스템 점검/정기 서버 점검 예측
  → 알파 없음, 스킵 시그널

Pattern C: 단일 체인 자산 이동 + 비정상 시간대
  예: 새벽 시간대 특정 체인만 이동
  → 긴급 점검 가능성
  → 시그널 발행 (신뢰도 중간)
```

### 3. 정상 vs 비정상 구분
```
정상적 핫→콜드 이동 (무시 대상):
  - 주기적/정기적 자금 이동 (매주 동일 시간대)
  - 소액 이동 (평균 잔고의 5% 미만)
  - 전 체인 동시 이동 (정기 점검)

비정상 이동 (시그널 대상):
  - 비정기 시간대
  - 특정 네트워크만 선별 이동
  - 평소 대비 대량 (잔고의 50% 이상)
  - 이동 직후 해당 네트워크 tx 급감
```

### 4. 시그널 발행
```
IF 특정 네트워크 자산만 핫→콜드 이동 감지
  AND 비정기 패턴
  AND 이동량이 유의미 (잔고의 20% 이상)
THEN:
  시그널 발행 (signal_type: "internal_maintenance_signal")
  예측: 해당 네트워크 입출금 정지 임박
  신뢰도: medium (05번보다 낮음)
```

## 데이터 의존성
- `19-data-registry`: 거래소 핫월렛 + 콜드월렛 주소 라벨링 DB
- `19-data-registry`: 거래소 정기 점검 스케줄 (정기 vs 비정기 구분용)
- `05-hot-wallet-abnormal-withdrawal`: 미확인 주소 이동은 05번으로 라우팅

## 모니터링 주기
- 핫월렛 → 콜드월렛 tx 폴링: **1분 간격**
- 정기 이동 패턴 학습: **일 1회** 통계 갱신

## 05번과의 구분
| 구분 | 05. 비정상 출금 | 06. 핫→콜드 이동 |
|------|---------------|----------------|
| 수신 주소 | 미확인/외부 | 동일 거래소 콜드월렛 |
| 의미 | 해킹 징후 | 내부 점검 징후 |
| 긴급도 | Critical | Medium |
| 포지션 방향 | 초기 금지 → 역프리미엄 추매 | 소규모 롱 + 숏 |
| 시그널 강도 | 강함 | 약함 |

## 엣지 케이스
- 콜드월렛 주소 변경: 라벨링 DB 주기적 갱신 필요
- 핫→콜드 이동 후 입출금 정지 안 됨: 오탐 학습, 패턴 DB 업데이트
- 정기 점검인데 비정기 시간대: 특수 이벤트(명절 등) 캘린더 참조
